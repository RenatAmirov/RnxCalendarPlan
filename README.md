# RNX Calendar Plan

Личный веб-планировщик самообучения C#/.NET и практики с ChatGPT/Codex. Включает подготовку к первому техническому собеседованию в **Т-Банке 23 ноября 2026 года в 09:00 МСК (10:00 Самара, 06:00 UTC)**.

## Возможности

- Обзор с обратным отсчётом, недельным планом и прогрессом по выполненным занятиям.
- Календарь: месяц, неделя, список; фильтрация направлений; экспорт всего плана в `.ics`.
- Создание, редактирование и удаление занятий, статусы, ожидаемый результат и личные заметки. Предупреждение о пересечении времени.
- 12 тем с вопросами для самопроверки, ссылками на официальные материалы, конспектами и самооценкой 0–3.
- Четыре сценария AI-практики с копированием промптов для ChatGPT/Codex. Промпт интервью использует актуальные компанию, этап и время цели; изменение цели учитывается при следующем открытии промпта. Запросы к платному API не выполняются.
- Переключение московского и самарского времени. Хранение дат в UTC, независимое от часового пояса браузера и сервера.
- Таймер фокуса на 25 минут, поиск по занятиям, заметкам и темам (`Ctrl+K`).
- Редактируемая цель собеседования. Длительность **60 минут — предположение для календаря**, её следует уточнить у рекрутера.

Занятия и собеседование отображаются в хронологическом порядке во всех видах календаря. При переходе между месяцем, неделей и списком сохраняется выбранная дата, включая переход через конец месяца и года.

Начальный план: **13 занятий, 11 ч 50 мин**, 20–23 ноября. Все занятия изначально не выполнены. Самооценка тем заполняется пользователем; она не является прогнозом результата интервью. Учебный план основан на типовых темах .NET и не выдаётся за официальную программу Т-Банка.

## Стек и устройство

**C# / .NET 10, ASP.NET Core Minimal API, EF Core 10, PostgreSQL 18 (Npgsql), Redis, NLog.** Интерфейс — HTML/CSS/JavaScript без отдельной сборки Node.js и внешних CDN.

```text
src/RnxCalendarPlan.Web/
  Domain/             Занятия, темы, цель
  Data/               DbContext, миграции PostgreSQL, атомарное начальное заполнение
  Features/           HTTP API, валидация, каталог промптов, экспорт iCalendar
  wwwroot/            Русскоязычный адаптивный интерфейс
  nlog.config         Консоль и структурированные JSON-логи
tests/                Проверки API на настоящем PostgreSQL, экспорта и отказа кеша
scripts/              Запуск изолированной инфраструктуры Windows
```

PostgreSQL — источник данных. Redis кеширует шаблоны промптов на 24 часа; при отказе кеша шаблоны доступны из приложения. Детали цели подставляются после чтения шаблона и не сохраняются в Redis. Занятия и заметки читаются из БД, поэтому инвалидация кеша для пользовательских изменений не нужна. EF Core защищает изменения полем `Version`: устаревшая запись возвращает HTTP 409. Начальные данные добавляются один раз, в транзакции с PostgreSQL advisory lock; удалённые занятия не восстанавливаются при перезапуске.

Это приложение для одного пользователя, доступное по loopback. Встроенной регистрации пользователей и разделения данных по аккаунтам нет.

## Запуск через Docker

Нужен запущенный Docker Desktop с Linux containers:

```powershell
docker compose up --build -d
```

Откройте [http://127.0.0.1:5080](http://127.0.0.1:5080). Миграции и начальное заполнение применяются автоматически. PostgreSQL и Redis имеют healthcheck; приложение запускается после их готовности. Healthcheck веб-контейнера проверяет настоящий HTTP-эндпоинт `/health`, поэтому состояние `healthy` требует готовности приложения и БД. Данные и логи сохраняются в именованных volumes.

Для запуска с ожиданием готовности всех компонентов: `docker compose up --build -d --wait`.

```powershell
docker compose logs -f web
docker compose down
```

`down` сохраняет volumes. Порты Docker привязаны к `127.0.0.1`: приложение `5080`, PostgreSQL `25432`, Redis `26379`. Их можно изменить через `APP_PORT`, `POSTGRES_PORT`, `REDIS_PORT` в `.env`. Порты БД и Redis отличаются от запуска без Docker (`15432` / `16379`); порт приложения по умолчанию общий, поэтому одновременно два веб-экземпляра на `5080` запускать нельзя.

Docker хранит план в именованном volume, а запуск без Docker — в `.local/postgres`. Это независимые хранилища; переключение способа запуска не переносит данные автоматически.

Для локальной разработки используется демонстрационный пароль `rnx_local_dev`. Переопределить его для Compose можно переменной `POSTGRES_PASSWORD` в `.env` (пример — `.env.example`).

## Запуск в Windows без Docker

Требования: SDK .NET 10, бинарные файлы PostgreSQL 18 и Redis. Скрипт использует установленные программы, создаёт **отдельный кластер PostgreSQL и отдельный Redis внутри `.local`** и не меняет системные службы или их базы.

```powershell
.\scripts\Start-Local.ps1
```

По умолчанию программы находятся в `C:\Program Files\PostgreSQL\18\bin` и `C:\Program Files\Redis`. Другие пути задаются параметрами `-PostgresBin` и `-RedisBin`. Приложение запускается в текущем терминале. Остановить приложение: `Ctrl+C`.

Для фонового запуска без открытого терминала:

```powershell
.\scripts\Start-Local.ps1 -Background
```

Скрипт публикует Release в `.local/app`, запускает процесс в скрытом окне и проверяет `/health` перед сообщением о готовности. Повторный запуск использует уже работающий экземпляр проекта. Вывод находится в `.local/web.stdout.log`, `.local/web.stderr.log` и `.local/app/logs`. Для применения изменений исходников остановите приложение и запустите скрипт снова.

Остановить фоновое приложение и инфраструктуру проекта, сохранив данные:

```powershell
.\scripts\Stop-Local.ps1
```

Остановка проверяет принадлежность процессов проекту, в том числе время запуска фонового .NET-процесса. Повторная остановка допустима. Экземпляр, запущенный вручную через `dotnet run`, останавливается в его терминале.

Если PostgreSQL/Redis уже настроены самостоятельно, создайте отдельную базу и укажите подключения через переменные окружения либо `src/RnxCalendarPlan.Web/appsettings.Local.json` (см. `appsettings.Local.example.json`):

```powershell
$env:ConnectionStrings__Postgres = 'Host=localhost;Port=5432;Database=rnx_calendar;Username=YOUR_USER;Password=YOUR_PASSWORD'
$env:ConnectionStrings__Redis = 'localhost:6379,abortConnect=false,connectTimeout=1000,asyncTimeout=1000'
dotnet run --project src/RnxCalendarPlan.Web
```

`appsettings.Local.json` и `.env` исключены из Git. Приоритет: базовые настройки → локальный файл → переменные окружения.

## Проверки

Интеграционные тесты создают случайную базу `rnx_test_<guid>` и удаляют её после выполнения. Данные рабочего плана не затрагиваются. Учётная запись тестового PostgreSQL должна иметь право создавать базы.

```powershell
.\scripts\Start-Local.ps1 -InfrastructureOnly
dotnet test RnxCalendarPlan.sln
dotnet build RnxCalendarPlan.sln -c Release
node --check src/RnxCalendarPlan.Web/wwwroot/app.js
node --test tests/frontend/calendar.test.mjs
docker compose config --quiet
```

Для другого тестового сервера задайте `RNX_TEST_POSTGRES` со строкой подключения; имя базы будет заменено случайным тестовым именем. Для PostgreSQL из Docker укажите порт `25432`. Node.js нужен только для проверки синтаксиса и тестов календарных функций, не для работы приложения.

Проверяются: исходная дата собеседования, CRUD с UTC-нормализацией, сохранение заметок, защита обновления/удаления от конфликтов, валидация ввода, самооценка тем, изменение цели и актуальный контекст промпта, HTTP-ответы экспорта, экранирование и UTF-8 folding iCalendar, доступность промптов при отказе Redis. Тесты JavaScript проверяют границы суток в разных поясах, високосный февраль, переходы между месяцами и годами, порядок разминки и интервью.

## HTTP API

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/plan` | Занятия, темы, цель и текущее время UTC |
| POST | `/api/sessions` | Создать занятие |
| PUT | `/api/sessions/{id}` | Обновить занятие с `version` |
| DELETE | `/api/sessions/{id}?version=N` | Удалить занятие с проверкой версии |
| PUT | `/api/topics/{id}` | Сохранить `mastery` 0–3, `notes`, `version` |
| PUT | `/api/goal` | Изменить цель с проверкой версии |
| GET | `/api/prompts` | Каталог промптов через Redis с резервным чтением |
| GET | `/api/export/calendar.ics` | Экспорт занятий и цели с UTC-датами |
| GET | `/health` | Состояние PostgreSQL и Redis |

Пример создания:

```json
{
  "title": "Разобрать async/await",
  "track": "csharp",
  "kind": "practice",
  "startsAt": "2026-11-21T10:00:00+03:00",
  "durationMinutes": 60,
  "status": "planned",
  "topicId": "async",
  "outcome": "Объяснить отмену и Task.WhenAll",
  "notes": ""
}
```

Направления: `csharp`, `dotnet`, `data`, `ai`. Форматы: `theory`, `practice`, `review`, `mock`. Статусы: `planned`, `inProgress`, `completed`. Ответ создания содержит `id` и `version`. Ошибки валидации возвращаются как Problem Details (400), конфликт версии — 409. Длительность занятия — 5–480 минут.

`/health` возвращает 200 при доступной БД, включая `degraded` при недоступном Redis, и 503 при недоступной БД. NLog пишет JSON-логи в `logs/planner-YYYY-MM-DD.log` рядом со сборкой, хранение — 14 дней. Содержимое личных заметок в прикладные логи не записывается.

## Миграции

```powershell
dotnet tool restore
dotnet ef migrations add MigrationName --project src/RnxCalendarPlan.Web --output-dir Data/Migrations
dotnet ef database update --project src/RnxCalendarPlan.Web
```

Автоматические миграции можно выключить через `Database__MigrateOnStartup=false` после предварительного применения миграций. Начальное заполнение выполняется при включённом автоматическом запуске миграций.
